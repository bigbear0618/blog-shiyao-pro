Happy + Claude Code
让 AI 编程助手 7×24 在线

手机随手一开就能继续昨天的重构 — 把 Claude Code 部署到云服务器上，用 Happy 客户端远程接入，编程不再被设备绑死。

2026-06-04 · shiyao

📌 想解决什么问题

把 Claude Code 装在本地很方便，但有几个明显的限制：电脑合盖任务就停了；通勤路上灵感来了只能记笔记； 跨设备切换得重新拉仓库、配环境；长时间跑的任务（比如批量代码迁移、跑测试）必须开着机器守着。

解决方案出乎意料地简单 — 把 Claude Code 装在一台始终在线的云服务器上，本地（电脑/手机）只装一个 Happy 客户端去远程连。 服务器永不下线，客户端只是一个"窗口"，关了再开任务还在跑。

任意客户端都连接到同一台服务器上的 Claude 会话 — 也就是说在地铁上用手机发一句"把刚才那个 bug 修完"， 到家开电脑可以直接看到执行结果和后续对话。会话状态不属于设备，属于服务器。

⚡ 这个组合为什么好

7×24 不掉线

云服务器永远在线，关上电脑任务继续跑。长时间的重构、批量改动都不用守着。

跨设备无缝

手机、平板、笔记本都是同一个 Claude 会话的"窗口"，切换设备无需重新对齐上下文。

地铁也能开发

移动端的 Happy 把 Terminal、Claude 对话浓缩成手机能用的界面 — 通勤时也能改 PR。

统一环境

编辑器、依赖、工具链都装在服务器上一份，永远不会出现"我本机能跑你不行"。

低延迟出网

海外 ECS 直连 Anthropic API，省去代理 / 中转，请求-响应更顺。

成本可控

一台 2 核 1.8GB 的 ECS 月成本几十块，跑 Claude Code 完全够用，远比买顶配本子划算。

🚀 30 分钟搭起来

1. 准备一台海外 ECS

1 核 1G 起步（实测 1.6G 内存跑 Node 22 + Claude Code 很从容）。系统建议 Alinux 4 / Ubuntu 22+ / Debian 12。

2. 装 Node + Claude Code

# 装 NVM（Node 版本管理）
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.1/install.sh | bash
source ~/.zshrc

# 装 Node 22 LTS
nvm install 22
nvm use 22

# 装 Claude Code
npm install -g @anthropic-ai/claude-code

# 装 Happy 服务端（用于客户端远程接入）
npm install -g happy-coder

3. 登录 Claude / 配置 API Key

claude        # 首次跑会引导登录或粘贴 API Key
# 完成后可以加个别名,免去重复输入授权参数
echo 'alias ccdp="claude --dangerously-skip-permissions"' >> ~/.zshrc

4. 启动 Happy 接受远程连接

在服务器上跑 happy，它会生成一个一次性配对码或二维码。手机 / 本地 Happy 客户端扫码后即可远程连入这台服务器，所有命令都在云端执行。

💡 Tips
  • 给账号开 NOPASSWD sudo 后，Claude Code 在自动化任务里就不会卡在密码提示上。
  • 用 tmux 或 systemd 守住 Happy 进程，断网重连不丢会话。
  • 把项目目录放在 ~/projects/，Claude 的索引/缓存集中在一处更好备份。

"一行命令发布一篇文章"

上面这些节点配好以后，我把"复制文件 + 改权限 + 更新首页列表"这三件机械活封装成一个脚本 publish-blog（放在 /usr/local/bin/）。 从这一刻开始，发布一篇文章就只是一行： 

# 自动从 HTML 提取 <title> 和 description,自动更新首页列表
publish-blog ./my-post.html --tag DevOps

# 修改后重发(幂等,不会在首页留下重复条目)
publish-blog ./my-post.html --tag DevOps --force

# 只发布单页,不动首页
publish-blog ./my-post.html --no-index

脚本背后做的事:

  • 校验 slug — 只允许 [a-zA-Z0-9_-]，防路径穿越。
  • 自动提取标题和摘要 — 从 HTML 的 <title> 和 <meta name="description"> 读取，省得手抄。
  • 权限对齐 — chown nginx:nginx + chmod 644，避免 403。
  • 幂等的首页插入 — 用 awk 在首页模板的注释 marker 前插入条目；如果同 slug 已存在，先删旧再插新，多次 --force 结果不变。
  • 无需 reload — nginx 看的是磁盘文件，新建/更新 HTML 立即生效，不用重启服务。
💡 为什么这套链路这么轻

没有数据库、没有构建工具、没有 SSG、没有任何运行时 — 只是"HTML 文件 + nginx + 一个脚本"。 但因为 Claude Code 能直接生成成品 HTML，"全静态"反而成了 AI 时代的最佳实践: 内容生成在云端， 分发由几十年成熟的 nginx 兜底，整条链路没有任何会出问题的中间层。

🐙 与 GitHub 联动 — 让 Claude 顺便把 git 也包了

服务器上 gh CLI 和 git 都已配好（这台机器上跑的是 gh 2.93.0 + git 2.47.3， 作者邮箱已绑定）— 这意味着 Claude Code 在跟你聊代码的同时，也可以直接处理 GitHub 相关的事:

克隆 & 切分支

一句话:"把 repo X 拉下来，新开 feature/y 分支"，剩下不用管。

提交 & 推送

改完代码让 Claude 自己写 commit message — 它知道仓库的提交风格。

开 PR & 写描述

gh pr create 自动生成 PR 标题、摘要、测试清单。

看 issue & 改

"看下 issue #42 然后修一下" — Claude 用 gh issue view 拉取上下文再动手。

审 PR 给评论

gh pr diff + Claude 评审，把意见用 gh pr comment 直接贴回去。

合并 & 清理分支

gh pr merge --squash --delete-branch — 一行收尾。

把博客源码也丢进 GitHub

这套静态站点最适合用 git 管：

# 在服务器上(或本地)初始化博客仓库
cd ~/projects/blog
git init && gh repo create blog --private --source=. --remote=origin

# 把所有 .html 提交进去
git add . && git commit -m "init"
git push -u origin main

之后两种部署姿势二选一：

姿势 A: 服务器 pull (最简)

# 在源码仓库写好新文章,提交推到 GitHub
git add new-post.html && git commit -m "post: 新文章" && git push

# 服务器拉取后用 publish-blog 部署
ssh ecs "cd ~/projects/blog && git pull && publish-blog new-post.html --tag 笔记"

姿势 B: GitHub Actions 自动部署 (省手动)

在仓库加一个 workflow，监听 push 到 main，用 SSH key 登录 ECS 跑 publish-blog。 关键步骤:

  1. 在 GitHub repo settings 加 secrets: SSH_PRIVATE_KEY、SSH_HOST、SSH_USER。
  2. workflow 用 appleboy/ssh-action 之类的 action，把变更过的 *.html rsync 到服务器，调用 publish-blog。
  3. 之后写文章只需要本地 git push — CI 跑完，文章自动上线。
🔁 闭环

本地手机/电脑 → Happy 客户端 → 云端 Claude Code → 改 git 仓库的 HTML → 推 GitHub → 自动部署到 nginx → 全网立即可读。 整套流程里，真正"手动"的环节只剩"想要写什么"。

🛡 安全提醒

  • SSH 必须只允许 key 登录，禁掉密码。
  • Happy 的配对码 / token 不要外泄 — 等同于一把进入终端的钥匙。
  • 云厂商的安全组 / 防火墙只放行需要的端口（22、80、443、Happy 监听端口）。
  • 开了 NOPASSWD sudo 就务必把 SSH key 用得严格 — 钥匙泄漏 = root 泄漏。
  • API Key 保存在服务器上，写入 ~/.claude，注意备份目录别被打包外发。

📝 写在最后

过去十年我们一直在追求"个人电脑本身要够强"，但 AI 时代把这件事彻底翻了过来 — 真正需要"够强"的是 持续在线的算力 + 不断累积的会话上下文，本地设备只是一块"屏幕"。

Happy + Claude Code 这个组合用最朴素的方式诠释了这一点：把脑子放在云上，把眼睛留在身边。 装好之后会发现，"开发"这件事再也不是"打开电脑"开始的 — 而是从来没有停止过。
