HTML Video 使用指南
用网页技术生成 MP4

把 HTML、CSS、JavaScript 当成视频工程来写：浏览器负责预览，渲染器逐帧输出，最后得到一个可以发到 YouTube、抖音、官网和产品页里的 MP4。

2026-06-05 · shiyao

先把概念说清楚

这里说的 HTML Video，不是传统意义上的 <video> 标签，也不是把 MP4 嵌进网页。 它指的是一种 HTML-to-video 工作流：用网页技术写画面、动效、字幕、图表和音频，再把这个网页按时间轴渲染成视频文件。

这个方向最近值得关注的工具是 HyperFrames。 它的思路很直接：一段普通 HTML 声明画布尺寸、时长、帧率和每个元素的出现时间；开发时像调网页一样实时预览；发布时用 CLI 渲染成 MP4。

它适合做什么

产品演示视频

把 App 截图、网页界面、功能路径写成可复用模板，每次发布新版本只换素材和文案。

数据可视化短片

JSON、CSV、API 数据进来，柱状图、排行榜、指标卡按时间动起来，适合周报和运营内容。

社媒短视频模板

同一份 HTML 输出 16:9、9:16、1:1，多平台只改尺寸和版式约束。

AI Agent 自动出片

让 Codex / Claude 写 HTML、跑预览、修截图、再渲染，整个过程可以像写代码一样进入版本管理。

为什么不用直接录屏

录屏最快，但它很难稳定复现。鼠标抖一下、网络慢一下、系统通知弹一下，视频就要重录。 HTML-to-video 的优势是 视频源文件本质上是代码：能 diff，能复用，能批量生成，也能放进 CI。

方式优点短板
录屏 启动快，真实展示产品 难复现，批量化差，字幕和动效后期成本高
剪辑软件 自由度最高，适合复杂创意 工程自动化弱，模板化成本高
HTML Video 可编程、可预览、可复现、适合 AI 生成 不适合真人实拍和复杂电影级特效

5 分钟跑通第一条视频

按 HyperFrames 官方 Quickstart，最小路径就是装 CLI、初始化工程、预览、渲染。 如果只是试水，可以先用它的在线 Playground；要稳定输出 MP4，建议本地或服务器装 CLI。 

npm install -g hyperframes
hyperframes init hello-video
cd hello-video

# 浏览器预览,支持 live reload 和时间轴控制
hyperframes preview comp.html

# 渲染成 MP4
hyperframes render comp.html --out video.mp4

一个最小 composition 长这样：

<!doctype html>
<div data-width="1920" data-height="1080" data-duration="5" data-fps="60">
  <div data-start="0" data-duration="5" class="bg"></div>
  <h1 data-start="1" data-duration="4" data-fade="in">
    Hello, friend.
  </h1>
</div>

这段 HTML 里最重要的是四类信息： data-width / data-height 定义画布， data-duration 定义总时长或元素持续时间， data-fps 定义帧率， data-start 定义元素从第几秒开始出现。

我建议的项目结构

不要把视频工程写成一个越来越大的 HTML 文件。哪怕只是个人项目，也建议一开始就把素材、数据、脚本分开。

launch-video/
├── comp.html              # 主 composition
├── package.json
├── assets/
│   ├── screenshots/
│   ├── logo.svg
│   └── music.mp3
├── data/
│   └── metrics.json
└── renders/
    ├── launch-16x9.mp4
    ├── launch-9x16.mp4
    └── launch-square.mp4
我的默认规则
  • 一条视频一个目录，避免素材串台。
  • 所有关键参数写在 HTML 根节点或配置文件里，不靠口头约定。
  • 渲染产物放 renders/，源文件和产物分开。
  • 能用真实截图就不用抽象插画，尤其是产品 demo。

给 AI Agent 的提示词模板

HTML Video 最大的增益，是它特别适合交给 AI 编程助手处理。比起“帮我剪一个视频”，更好的说法是把目标拆成规格、分镜、素材和验收条件。 

用 HTML-to-video 的方式做一个 25 秒产品发布视频。

规格:
- 1920x1080, 60fps, H.264 MP4
- 5 个镜头: 标题、问题、核心功能、结果、CTA
- 使用 assets/screenshots 里的真实产品截图
- 字幕必须在安全区内,移动端裁切也能看清

实现:
- 写 comp.html
- 用 CSS/JS 做时间轴动画
- 先启动 preview 检查画面
- 渲染 video.mp4

验收:
- 首帧不能黑屏
- 每个镜头转场不超过 0.5 秒
- 文案不遮挡产品界面
- 输出前截图检查 0s / 5s / 10s / 15s / 20s / 24s

重点是最后的验收条件。AI 很容易把视频做成“看起来有东西动”，但真实可用的视频要看首帧、字幕安全区、转场节奏、品牌露出和最终 CTA。

常用命令清单

动作命令用途
初始化 hyperframes init hello-video 生成一个带 comp.html 的新项目
预览 hyperframes preview comp.html 启动本地预览和时间轴控制
检查 hyperframes lint comp.html 提前发现时长、属性、资源引用问题
查看信息 hyperframes inspect comp.html 输出时长、fps、轨道和依赖信息
渲染 hyperframes render comp.html --out video.mp4 输出最终 MP4

实战注意事项

坑 1 · 把网页动画当视频动画

网页动画可以“差不多顺”，视频不行。关键节点要按秒或帧设计：第几秒出现标题、第几秒进入截图、第几秒 CTA 停住，都要明确。

坑 2 · 素材没有固定尺寸

产品截图、头像、图标最好先统一尺寸或写死容器比例。否则同一套模板换素材后，画面会跳、文字会挤、裁切会乱。

坑 3 · 忘了音频版权

HTML 里引用音乐很容易，但发布到公开平台前要确认授权。内部 demo 可以快，公开发布不能随便拿一段 BGM。

坑 4 · 只看预览不看产物

最终判断以渲染出来的 MP4 为准。导出后至少检查首帧、末帧、字幕、音量、黑边、码率和目标平台的裁切效果。

什么时候该选它

我的判断很简单：

  • 如果视频内容来自数据、截图、文案、模板，选 HTML Video。
  • 如果要一周批量出几十条不同版本，选 HTML Video。
  • 如果要 AI 直接参与生产和修改，选 HTML Video。
  • 如果是真人口播、复杂合成、电影级调色，还是用传统剪辑软件。
