html-video 使用指南
Agent 写 HTML，本地导出 MP4

结合 Tom Huang 开源的 nexu-io/html-video，把“HTML-to-video”从底层渲染能力升级成一套 Agent 可直接使用的视频制作工作流：模板、分页编辑、文章/Repo 输入、配音配乐和 MP4 导出都放到一个本地 Studio 里。

2026-06-05 · shiyao

先把概念修正一下

这里说的 HTML Video，不是传统意义上的 <video> 标签，也不是把 MP4 嵌进网页。 它指的是一种 HTML-to-video 工作流：用网页技术写画面、动效、字幕、图表和音频，再把这个网页按时间轴渲染成视频文件。

但只说 HyperFrames 还不够准确。HyperFrames 更像底层渲染引擎：HTML + CSS + GSAP 进来，Headless Chromium 逐帧录制，ffmpeg 编码成视频。 html-video 则是站在它上面的 Agent meta-layer： Agent 读文章、读 GitHub repo、挑模板、生成分镜和每帧 HTML，Studio 负责预览、分页编辑、音频和导出。

这条 X 文档带来的关键更新

Tom Huang 在 X 上正式宣布开源 html-video，定位很明确：HTML 版剪映。 它不是又一个单纯的渲染 CLI，而是让 Claude Code、Codex、Cursor、Hermes 等本地 Coding Agent 能“写 HTML 做视频”的工作台。

原来我文章里的理解现在应该改成
HTML Video = 直接写 HyperFrames composition HTML Video = Agent meta-layer + 模板库 + Studio + 渲染引擎，HyperFrames 是当前已接好的默认引擎。
重点是写一个 HTML 文件 重点是把文章、链接、Repo 或 prompt 变成 content-graph，再拆成多帧可编辑 HTML。

模板自己找、自己改 项目内置 21 套 license-clean 模板，并用 manifest 描述适用场景、输入 schema、授权和输出规格。

它适合做什么

产品演示视频

把 App 截图、网页界面、功能路径写成可复用模板，每次发布新版本只换素材和文案。

数据可视化短片

JSON、CSV、API 数据进来，柱状图、排行榜、指标卡按时间动起来，适合周报和运营内容。

社媒短视频模板

同一份 HTML 输出 16:9、9:16、1:1，多平台只改尺寸和版式约束。

AI Agent 自动出片

让 Codex / Claude 写 HTML、跑预览、修截图、再渲染，整个过程可以像写代码一样进入版本管理。

为什么不用直接录屏

录屏最快，但它很难稳定复现。鼠标抖一下、网络慢一下、系统通知弹一下，视频就要重录。 HTML-to-video 的优势是 视频源文件本质上是代码：能 diff，能复用，能批量生成，也能放进 CI。

方式优点短板
录屏 启动快，真实展示产品 难复现，批量化差，字幕和动效后期成本高
剪辑软件 自由度最高，适合复杂创意 工程自动化弱，模板化成本高
HTML Video 可编程、可预览、可复现、适合 AI 生成 不适合真人实拍和复杂电影级特效

核心 Pipeline

html-video 的 README 把流程说得很清楚：一句话、一个链接或一个 GitHub repo 进去，最终输出一个真实 MP4。 中间最关键的是 content-graph，它把“文章重点、因果关系、对比关系、镜头顺序和 timing”变成 Agent 与渲染引擎之间的中间层。 

prompt / link / repo
  ↓
source fetch
  # 服务端抓取文章或 GitHub repo, 展平成 Markdown
  ↓
agent loop
  # 本地 Agent 读取材料 + 模板说明, 生成 storyboard
  ↓
content-graph
  # 多帧 IR: nodes + edges + sequence + timing
  ↓
per-frame HTML
  # 每个节点变成一个自包含 animated HTML frame
  ↓
HyperFrames render
  # Headless Chromium 录制每帧动画, 生成 webm
  ↓
ffmpeg
  # webm 转 mp4, 拼接, 可选混入 MiniMax 音乐和旁白
  ↓
your.mp4

5 分钟跑通 html-video

如果你要体验的是 Tom 这次开源的 html-video，而不是单独使用 HyperFrames，入口应该走它的本地 Studio。 官方 README 的最短路径如下： 

git clone https://github.com/nexu-io/html-video.git
cd html-video
pnpm install
pnpm -r build

# 打开本地 Studio: http://127.0.0.1:3071
node packages/cli/dist/bin.js studio

打开 Studio 后，你可以直接描述视频、粘贴文章链接、粘贴 GitHub repo，或者选择模板后让 Agent 填内容。 Studio 会检测本地可用 Agent：Open Design / Claude Code / Cursor Agent / Codex CLI / Hermes； 如果没有装 CLI，也可以用 Anthropic Messages API BYOK。

项目架构

html-video 的目录结构体现了它的定位：不是单一 renderer，而是 Studio、Agent runtime、模板、content-graph 和引擎 adapter 的组合。

packages/
├── core/                  # Project / Asset / ContentGraph / orchestrator
├── content-graph/         # 多帧 storyboard IR: nodes + edges + topo-sort
├── runtime/               # Agent runtime: Claude / Cursor / Codex / Hermes / API
├── adapter-hyperframes/   # 当前已接入的渲染引擎: Chromium + ffmpeg
├── cli/                   # html-video 命令、本地 Studio、source fetching
└── project-studio/        # 浏览器 UI: chat / templates / frames / soundtrack / export

templates/                 # 21 套 curated video templates
research/                  # adapter / metadata / agent skill / content-graph RFC
我的默认规则
  • 不要让 Agent 从零发明风格，优先让它选一个模板 manifest。
  • 文章 / Repo 视频先生成 content-graph，再改每帧文案，别直接改最终 MP4。
  • 把音频当成导出阶段的一部分：旁白、BGM、ducking、fade 都应该可复现。
  • 如果只做单镜头标题卡，可以走 single-frame fast path；多段解说要走 content-graph。

给 AI Agent 的提示词模板

html-video 最大的增益，是把“写视频”变成 Agent 能理解的工程任务。比起“帮我剪一个视频”，更好的提示词是给出素材来源、目标受众、模板偏好、镜头数量、音频要求和验收条件。 

用 html-video 做一个 30 秒产品发布视频。

规格:
- 1920x1080, 60fps, H.264 MP4
- 输入材料: https://github.com/example/project
- 选择适合产品发布的多帧模板
- 5 个 frames: 标题、痛点、核心功能、真实界面、CTA
- 需要旁白和轻量背景音乐

实现:
- 先把 repo README 和目录结构转成 content-graph
- 每帧文案都要能追溯到 repo 里的真实信息
- 生成 per-frame HTML 后让我在 Studio 里编辑确认
- 最后导出 MP4

验收:
- 首帧不能黑屏
- 字幕不能遮挡产品 UI
- CTA 停留至少 3 秒
- 背景音乐要 duck 在旁白下面
- 导出前检查每个 frame 的文案和 timing

重点是最后的验收条件。AI 很容易把视频做成“看起来有东西动”，但真实可用的视频要看首帧、字幕安全区、转场节奏、品牌露出和最终 CTA。

实战注意事项

坑 1 · 把网页动画当视频动画

网页动画可以“差不多顺”，视频不行。关键节点要按秒或帧设计：第几秒出现标题、第几秒进入截图、第几秒 CTA 停住，都要明确。

坑 2 · 素材没有固定尺寸

产品截图、头像、图标最好先统一尺寸或写死容器比例。否则同一套模板换素材后，画面会跳、文字会挤、裁切会乱。

坑 3 · 忘了音频版权

HTML 里引用音乐很容易，但发布到公开平台前要确认授权。内部 demo 可以快，公开发布不能随便拿一段 BGM。

坑 4 · 只看预览不看产物

最终判断以渲染出来的 MP4 为准。导出后至少检查首帧、末帧、字幕、音量、黑边、码率和目标平台的裁切效果。

什么时候该选它

我的判断很简单：

  • 如果视频内容来自文章、GitHub repo、数据、截图、文案、模板，选 html-video。
  • 如果你希望本地 Agent 直接参与生产和修改，选 html-video。
  • 如果你只需要一个极简 HTML composition，直接用 HyperFrames 也够。
  • 如果是真人口播、复杂合成、电影级调色，还是用传统剪辑软件。
